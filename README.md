# 17. Свой монитор сайтов и серверов: узнаёшь о падении раньше клиента (Uptime Kuma в Docker)

Материалы к ролику №17 канала «ByteAutomate | Код и AI». Новые материалы и файлы: канал в Telegram [@ByteAutomate_AI](https://t.me/ByteAutomate_AI).

## Что это

[Uptime Kuma](https://github.com/louislam/uptime-kuma) это открытая программа (лицензия MIT) для мониторинга: она каждую минуту проверяет ваши сайты и серверы и при падении присылает сообщение, например в Telegram. Работает на вашем сервере, абонентской платы за программу нет; платите только за свой сервер (VPS), если его ещё нет.

В этом наборе: готовый `docker-compose.yml` для запуска, `.env.example` с настройками и скрипт `check_ssl_expiry.py`, который отдельно проверяет срок SSL сертификатов.

## Запуск одной командой

Нужен Linux-сервер (или мини-ПК) с установленными Docker и Docker Compose ([официальная инструкция по установке Docker](https://docs.docker.com/engine/install/)).

```bash
cp .env.example .env
docker compose up -d
docker compose ps
```

По умолчанию панель слушает только `127.0.0.1:3001`, снаружи она недоступна (так безопаснее). Чтобы открыть её со своего компьютера, сделайте SSH-туннель:

```bash
ssh -L 3001:127.0.0.1:3001 пользователь@адрес_сервера
```

и откройте в браузере `http://localhost:3001`. Для постоянного доступа настройте обратный прокси с HTTPS (Caddy, Nginx) и не открывайте порт 3001 в интернет без HTTPS и сильного пароля.

Дальше по шагам (первый вход, монитор сайта, бот в Telegram, предупреждение об SSL): [`Инструкция.txt`](Инструкция.txt).

## Как устроен мониторинг

```
ваш сайт / сервер  <--проверка раз в 60 с--  Uptime Kuma (Docker, отдельный сервер)
                                                   |
                                          при падении (Down)
                                                   v
                                      Telegram Bot API  -->  телефон
```

- Uptime Kuma хранит историю, мониторы и настройки в папке `./data` (база SQLite и конфигурация).
- Сообщения уходят через ваш бот Telegram: бот создаётся у `@BotFather`, токен и chat_id вводятся в интерфейсе Uptime Kuma (Settings, Notifications). Токен хранится внутри `./data`, в репозиторий и в `.env.example` он не попадает.
- Монитор ставьте **на отдельный сервер**: если упадёт машина, где живут и сайт, и монитор, сообщения не будет.

## Проверка SSL сертификатов

В Uptime Kuma пороги уведомлений об окончании сертификата настраиваются в Settings, Notifications (по умолчанию 7, 14 и 21 день); для монитора HTTP(s) включается уведомление об окончании сертификата. Названия пунктов в вашей версии могут отличаться.

Вторым рубежом работает скрипт из набора (Python 3.9+, только стандартная библиотека):

```bash
python check_ssl_expiry.py example.com shop.example.org --warn-days 14
python check_ssl_expiry.py --file sites.txt --telegram
```

Код возврата: `0` всё хорошо, `1` срок меньше порога, `2` ошибка или недействительный сертификат. С ключом `--telegram` проблемы уходят в вашего бота (переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`); без ключа скрипт ничего не отправляет. Скрипт можно запускать раз в сутки по расписанию (cron).

## Резервная копия по правилу 3-2-1

Вся история и настройки лежат в `./data`. Потеряете папку, потеряете всё. Держите **три копии** на **двух разных носителях**, **одну** из них в другом месте (другой сервер, внешний диск, независимое хранилище; шифруйте, если копия уходит наружу). Не удаляйте оригинал, пока копия не проверена: распакуйте её отдельно и убедитесь, что файлы на месте. Копии содержат токен Telegram-бота, храните их как секрет.

Минимальный порядок: `docker compose stop`, `tar -czf kuma-data-$(date +%F).tar.gz data`, `docker compose start`.

## Честные ограничения

- Мониторинг не даёт гарантий: проверка раз в минуту может пропустить короткий сбой, а сообщение в Telegram может задержаться из-за самого Telegram или вашей сети.
- Образ `louislam/uptime-kuma:2` и настройки взяты из официального README проекта на момент записи ролика (2026-10). Автор набор на рабочий сервер не устанавливал и в Docker не запускал; `check_ssl_expiry.py` проверен автотестом без сети и живым запуском на публичных сайтах (срок сертификата читается), ветка просроченных сертификатов на живом примере не проверялась.
- Порядок первого запуска и названия пунктов меню могут меняться между версиями Uptime Kuma: ориентир официальная страница проекта.
- Условия Docker, Telegram и хостинга проверяйте актуальные.
