СВОЙ МОНИТОР САЙТОВ И СЕРВЕРОВ: УЗНАЁШЬ О ПАДЕНИИ РАНЬШЕ КЛИЕНТА
Uptime Kuma в Docker Compose

------------------------------------------------------------
ЧТО ЭТО
------------------------------------------------------------
Uptime Kuma это открытая программа (лицензия MIT) для мониторинга: каждую минуту она проверяет ваши сайты и серверы и при падении присылает сообщение, например в Telegram. Работает на вашем сервере, абонентской платы за программу нет. Платите только за свой сервер (VPS), если у вас его ещё нет.
Рядом лежит маленький скрипт check_ssl_expiry.py: он отдельно проверяет, сколько дней осталось у SSL-сертификата сайта.

------------------------------------------------------------
ЧТО В АРХИВЕ
------------------------------------------------------------
  docker-compose.yml     запуск Uptime Kuma одной командой
  .env.example           настройки (порт, адрес, часовой пояс); секретов в нём нет
  check_ssl_expiry.py    проверка срока SSL-сертификатов (Python 3.9+, без установки пакетов)
  Инструкция.txt         этот файл

------------------------------------------------------------
ШАГ 0. ГДЕ ЗАПУСКАТЬ
------------------------------------------------------------
Нужен Linux-сервер (VPS) или домашний мини-ПК с установленным Docker и Docker Compose. Монитор должен стоять НА ОТДЕЛЬНОМ СЕРВЕРЕ от ваших сайтов: если упадёт сервер, где живёт и сайт, и монитор, сообщения не будет.
Аренда VPS: Timeweb Cloud по партнёрской ссылке автора https://timeweb.cloud/r/nf413716 (ссылка партнёрская: автор получает вознаграждение; бонус и тариф проверяйте на сайте, условия меняются).
Docker ставится по официальной инструкции: https://docs.docker.com/engine/install/

------------------------------------------------------------
ШАГ 1. ЗАПУСК
------------------------------------------------------------
  1. Скопируйте папку из архива на сервер, например в ~/uptime-kuma.
  2. cd ~/uptime-kuma
  3. cp .env.example .env
  4. docker compose up -d
  5. Проверьте: docker compose ps (контейнер uptime-kuma в состоянии running).
По умолчанию панель слушает только 127.0.0.1:3001 (снаружи недоступна: это безопаснее). Чтобы открыть её с вашего компьютера, сделайте SSH-туннель:
  ssh -L 3001:127.0.0.1:3001 пользователь@адрес_сервера
и откройте в браузере http://localhost:3001. Для постоянного доступа настройте обратный прокси с HTTPS (Caddy, Nginx) и не открывайте порт 3001 в интернет без HTTPS и пароля.

------------------------------------------------------------
ШАГ 2. ПЕРВЫЙ ВХОД
------------------------------------------------------------
При первом открытии панели создайте учётную запись администратора: придумайте логин и длинный уникальный пароль. В версии 2 программа может предложить выбрать базу данных: выберите SQLite (проще всего, не нужен отдельный сервер баз данных).

------------------------------------------------------------
ШАГ 3. ДОБАВЬТЕ МОНИТОР САЙТА
------------------------------------------------------------
  1. Кнопка «Add New Monitor» (добавить монитор).
  2. Monitor Type: HTTP(s). Friendly Name: любое имя. URL: адрес сайта с https://.
  3. Heartbeat Interval: 60 (проверка раз в минуту; обычно стоит по умолчанию).
  4. Для проверки сервера (не сайта) используйте тип Ping или TCP Port.
  5. Сохраните (Save). Монитор станет зелёным, а на странице появится шкала доступности.

------------------------------------------------------------
ШАГ 4. УВЕДОМЛЕНИЯ В TELEGRAM (через Telegram Bot API)
------------------------------------------------------------
  1. В Telegram найдите @BotFather, команда /newbot, придумайте имя бота. Получите токен бота (длинная строка). Токен это пароль бота: никому не показывайте и не публикуйте.
  2. Напишите своему новому боту любое сообщение (кнопка Start).
  3. Узнайте свой chat_id: после сообщения боту откройте в браузере адрес https://api.telegram.org/botВАШ_ТОКЕН/getUpdates и найдите в ответе "chat":{"id":ЧИСЛО}. (Адрес содержит токен: не отправляйте его другим и не выкладывайте скриншот.)
  4. В Uptime Kuma: Settings, Notifications, Setup Notification, тип Telegram. Вставьте токен бота (Bot Token) и chat_id, нажмите Test (должно прийти тестовое сообщение), затем Save.
  5. Включите пункт «Default enabled» или привяжите уведомление к каждому монитору.
Сообщение приходит и при падении (Down), и при восстановлении (Up).

------------------------------------------------------------
ШАГ 5. ПРЕДУПРЕЖДЕНИЕ ОБ SSL-СЕРТИФИКАТЕ ЗА 14 ДНЕЙ
------------------------------------------------------------
В Uptime Kuma: Settings, Notifications, блок «TLS Expiry»: набор порогов по умолчанию 7, 14 и 21 день. Оставьте отмеченным 14 (и при желании 21 и 7). Для монитора HTTP(s) отметьте «Certificate Expiry Notification». Сообщение придёт в ваш Telegram-бот, когда до окончания сертификата останется 14 дней. Названия пунктов в вашей версии могут отличаться.
Вторым рубежом работает скрипт из архива (нужен Python 3.9+, пакеты не нужны):
  python check_ssl_expiry.py example.com shop.example.org --warn-days 14
  python check_ssl_expiry.py --file sites.txt --telegram   (список сайтов в файле, итог в вашего бота)
Для --telegram задайте переменные TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID в окружении сервера (заполненный .env не публикуйте). Код возврата: 0 всё хорошо, 1 срок меньше порога, 2 ошибка или недействительный сертификат. Можно запускать по расписанию (cron) раз в сутки.

------------------------------------------------------------
ОБЯЗАТЕЛЬНО: РЕЗЕРВНАЯ КОПИЯ ПО ПРАВИЛУ 3-2-1
------------------------------------------------------------
Вся история, мониторы и настройки Uptime Kuma лежат в папке ./data (там база SQLite и конфигурация). Потеряете папку: потеряете всё. Правило 3-2-1: ТРИ копии данных, на ДВУХ разных носителях, ОДНА из них в другом месте (другой сервер, внешний диск дома, независимое хранилище). Разработчики многих систем сами советуют именно эту схему.
Минимальный порядок:
  1. Остановите контейнер на минуту, чтобы база не писалась в момент копирования:
       docker compose stop
       tar -czf kuma-data-$(date +%F).tar.gz data
       docker compose start
  2. Положите архив ещё на два места: внешний диск и независимое хранилище (другой сервер или облако, куда вы сами решили выгружать; шифруйте архив, если он уходит наружу).
  3. Не удаляйте оригинал, пока копия не проверена: распакуйте её в отдельную папку и убедитесь, что файлы на месте.
  4. Раз в месяц проверяйте, что копия по-прежнему восстанавливается.
Токен Telegram-бота хранится внутри ./data: копии храните как секрет (шифрование, не публиковать).

------------------------------------------------------------
ЧЕСТНЫЕ ОГРАНИЧЕНИЯ
------------------------------------------------------------
  - Мониторинг не даёт гарантий: проверка раз в минуту может пропустить короткий сбой, а сообщение в Telegram может задержаться из-за самого Telegram или вашей сети.
  - Монитор на том же сервере, что и сайт, при падении этого сервера промолчит. Ставьте его отдельно и, при необходимости, добавьте второй монитор у другого провайдера.
  - Токен бота и пароль администратора это секреты. Не оставляйте панель открытой в интернет без HTTPS и сильного пароля.
  - Версия Uptime Kuma и порядок первого запуска (например, выбор базы данных) могут меняться: ориентир официальная страница https://github.com/louislam/uptime-kuma и её вики.
  - Образ louislam/uptime-kuma:2 взят из официального README проекта на момент записи (2026-10). Автор эти файлы на рабочий сервер пока не устанавливал и в Docker не запускал; скрипт check_ssl_expiry.py проверен автотестом без сети (14 проверок: пороги, коды возврата, ошибки, список сайтов, отправка в Telegram) и живым запуском на публичных сайтах (срок сертификата читается); просроченный сертификат на живом примере не проверялся.
  - Docker, VPS и Telegram имеют свои условия использования: проверяйте актуальные.

------------------------------------------------------------
ЕСЛИ ЧТО-ТО НЕ ЗАПУСКАЕТСЯ
------------------------------------------------------------
  - «docker: command not found»: Docker не установлен, см. Шаг 0.
  - Панель не открывается по http://localhost:3001: проверьте SSH-туннель и docker compose ps; порт 3001 по умолчанию закрыт снаружи.
  - Тест Telegram не приходит: проверьте токен, что вы нажали Start у своего бота и что chat_id верный.
  - check_ssl_expiry.py пишет «НЕТ ДАННЫХ»: нет интернета, неверное имя сайта или закрыт порт 443.
